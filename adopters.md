### v0.7.0 prefixed-exports migration (open)

Contract [v0.7.0](SPEC.md#12-changelog) resolved [#43](https://github.com/JC-000/c64-lib-contract/issues/43) — two libraries linked into one PRG collided on the unprefixed `LIB_VERSION_*` / `LIB_ABI_VERSION` (§1) and `LIB_PRECALC_<name>_*` (§8.4) symbols, so a consumer could import manifest equates from at most one of them. The fix is additive and needs no flag day, but it does need every adopter to act:

1. **§1** — export `LIB_<X>_VERSION_{MAJOR,MINOR,PATCH}` and `LIB_<X>_ABI_VERSION`, aliasing the bare names to them under `.ifndef LIB_NO_BARE_EXPORTS`, in a translation unit that exports nothing else.
2. **§5** — move the aggregate manifest equates out of `src/lib_version.s` into `src/lib_manifest.s`, so importing one cannot drag the bare §1 names into the link.
3. **§8.4** — refresh `src/precalc_table.inc` from this repo's canonical root copy and pass the library prefix as the fifth `LIB_PRECALC_TABLE` argument.

The bare names remain **required** through v0.x and are removed at v1.0, so nothing breaks while this wave lands. Until a given library ships it, a consumer composing that library with another still falls back to the §8.0 `od65` out-of-band pattern for it — noting per v0.7.2 that `od65` reads objects, not archives.

## How to add your library

1. Read [SPEC.md](SPEC.md).
2. Open a PR against this repo adding a row to the status table above with current adoption state per section.
3. File tracking issues against your library's repo for each unimplemented section. Link them back to this contract repo in the issue body.
4. Cross-link this repo from your library's README so consumers can find the contract.
5. Update the row as sections land in subsequent releases.
6. **Enumerate precalculated tables** per SPEC [§8.0 catch loop](SPEC.md#80-bit-allocation-for-lib_x_shared_primitives). Required for every precalculated table that meets the §8.0 floor (≥ 256 B AND one of: REU-resident, hot-loop-read, page-aligned for fetch alignment). Two forms, both mandatory:
   - **`docs/precalc-tables.md`** in your library, one row per table: name, size, region (main RAM / REU bank / RODATA), source file, classification (curve-/algorithm-specific *or* potentially shareable), and the rationale for the classification.
   - **`LIB_PRECALC_TABLE` macro invocations** from one of your library's translation units. Copy `precalc_table.inc` verbatim from SPEC §8.0 into `src/precalc_table.inc`, `.include` it once, and emit one `LIB_PRECALC_TABLE "name", size, region, shared, "<X>"` per enumerated table, where `<X>` is your library prefix (the same one your §5 `LIB_<X>_*` equates use). As of contract v0.7.0 the macro exports six equates per table — the library-prefixed `LIB_<X>_PRECALC_<name>_{SIZE,REGION,SHARED}` plus the deprecated bare `LIB_PRECALC_<name>_*` triple, which is removed at v1.0. Cross-adopter audits grep on `_PRECALC_`, which matches both forms; the older `LIB_PRECALC_` pattern misses every prefixed export. The table *name* stays unprefixed — the prefix identifies the declaring library, never the table.

   Link `docs/precalc-tables.md` from your row in the status table above.

   **Intake reviewers MUST confirm step 6 is satisfied before merging the adopter PR.** A `LIB_PRECALC_*` export without a corresponding `docs/precalc-tables.md` row — or vice versa — blocks merge. A library that has no tables clearing the §8.0 floor still files `docs/precalc-tables.md` with a one-line "no tables above the floor" note and the rationale (e.g., "all internal scratch is single-byte ZP; rotation lookups are 16 B").
